## What changed

- `prisma/schema.prisma`: `User.status @default(ACTIVE)`; `PREVIEW` stays in `UserStatus` for old rows.
- `prisma/migrations/20261128030000_signup_active`: `ALTER TABLE "User" ALTER COLUMN "status" SET DEFAULT 'ACTIVE';`
  and nothing else (the same SQL `prisma migrate diff` gives for old vs new schema). **Javaris runs it on production
  before the build.**
- `actions.ts` `createAccount`: creates `ACTIVE`. Google sign-up gets the column default (s36 §1 tests both).
- `SignInForm.tsx`, `page.tsx`: `/sign-in?mode=new` opens Create account mode. Create account has an optional
  `Invite code (optional)` field with the hint "Have a code from Vienne? Enter it to join your family." The field has
  no `name`, so createAccount never gets it. It's kept in sessionStorage (`src/components/auth/signup-code.ts`), and
  the Add your child step redeems it with the existing `redeemInvite` once the parent is signed in, then forgets it.
  A failed sign-up, or a password sign-in, forgets it too. On the sign-in side, "No code yet? Request an invite" is
  now the link "Questions? Message Vienne" to `/#request-invite`. "New family with an invite code?" and "After you
  sign up, enter the invite code Vienne sent you." stay (A1's spec reads them).
- `AddChildrenForm.tsx` (new), `src/components/auth/AddChildStep.tsx` (new): the step in `AuthScreen`. Rows of
  "Child’s first name" and "Grade" (K, 1–6), "Add another child" up to 6, and "Continue" (`families.addMyChildren`,
  then a full load to Home). Under "Have an invite code?" is `InviteCodeForm`, unchanged. An invalid code typed at
  sign-up shows redeemInvite's own message there ("That code isn’t valid. Check it with Vienne.").
- `AppRoot.jsx`: a parent who isn't PAUSED and has no children gets the step instead of the app (one `getFamily`
  read per full load; the app shows while it's on its way, so nothing waits on it). Old PREVIEW rows keep their
  locked view, with the step as a card at the top, holding the code form (so exactly one InviteCodeForm). If
  addMyChildren says CONFLICT (children already there), the step steps aside.
- No screen under `src/ui/pages` changed.
