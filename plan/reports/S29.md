## Likely source of OSA's warning

The screen renders the same HTML on the server and the client. Nothing in it reads `window`, the time, random
numbers or the locale during render. The only client-only work is `RegisterServiceWorker`, and it runs in an effect.
`<html>` already has `suppressHydrationWarning`, but that covers only `<html>`'s own attributes and not the form.

The sign-in form has email and password fields, so password managers (1Password, LastPass, Bitwarden, Dashlane) and
autofill tools edit it before React hydrates: they add attributes like `data-1p-ignore`, `data-lastpass-icon-root`
or `data-com-onepassword-filled`, or insert icon elements into it. Translators (Google Translate, and Grammarly
on text) edit the text the same way. React reports these edits as a mismatch only in dev, and React's own warning
names this cause: "It can also happen if the client has a browser extension installed which messes with the HTML
before React loaded." Production React doesn't warn about attribute differences. That fits auth.spec.ts passing in
CI, where its console-error fixture would fail on any error.

To confirm it on OSA's machine, open `/sign-in` on dev in a guest or incognito window with extensions off. The
warning should go away. If it doesn't, paste the warning's `+`/`-` diff and reopen S29.
